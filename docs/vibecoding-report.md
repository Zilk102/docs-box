# Отчёт о вайбкодинге

**Инструмент:** Claude Code (модель Claude Sonnet 5.5) + MCP CodeMaps (граф зависимостей, проверка архитектуры и документации).
**Фактические затраты времени:** _заполнить вручную_. **Оставшиеся задачи:** см. «Три следующих улучшения» в README.

## Характерные запросы к ИИ
1. «Используя представленные файлы и mcp codemaps реализуй инструмент… должен открываться в GitHub Pages, не хранить в себе никаких данных, а работать только на импорт/экспорт базы, чтобы несколько специалистов по закупкам работали одновременно с одной базой». ИИ предложил архитектуру «статический клиент + файл базы + условная запись с ETag + слияние по записям» вместо бэкенда.
2. «Покрой тестами: учёт статуса документа, отсутствующие значения, изменение поля и новый договор того же формата» — тесты-«мутации» правят текст договоров (формат суммы, словесные даты, другой поставщик, переименованные файлы), а не код.
3. «Проверь через CodeMaps валидацию и документацию» — рефакторинг сложных функций и раздутых файлов (`app.js` → `state/session/app`, CSS → 3 файла).

## Ошибки ИИ и как они были найдены
- **Неверное поле статуса.** В `resolve.js` ИИ читал `a.signed`, хотя разбор кладёт значение в `a.status.signed`. Проект ДС попадал в «нужна проверка: нет даты подписания» *случайно* — итоговые числа были верны, поэтому ошибка была бы незаметна. Поймал тест, проверяющий причину (`kind === 'draft'`, `reason` «не подписан»), а не только итоговое значение. Исправлено, тест оставлен.
- **Неверный код ответа сервера.** Повторное создание базы (`If-None-Match: *` при существующем файле) возвращало 428 вместо 412. Поймал тест на конкурентную запись; в сервер добавлена таблица правил `WRITE_RULES`.
- **Сбой шелл-скриптов.** Несколько правок через heredoc не применились (ошибка кавычек) — выяснилось по отсутствию изменений в файлах; дальше правки делались через инструменты редактирования и проверялись `grep`/тестами.
- **Рефакторинг ради метрики.** CodeMaps сообщил о сложных функциях; часть (таблицы правил в сервере и в `amendmentEffect`) улучшила читаемость, а часть остаётся на границе порога (сложность 9–12) — оставлено сознательно, это шаблонный UI/HTTP-код.

## Как проверялось
`npm test` (42 теста), ручной прогон в браузере (два окна на одном сервере базы: загрузка в одном появляется в другом за ≤5 с, с подписью автора), `check_documentation` = 100 %, `validate_architecture_changes` (остаточные замечания перечислены выше).
